## Milestone 1 — update review (October 26, 2026, Claude Code on the development server)

Implemented in `src/updates.ts` against the unchanged planner/verifier: intake `Source` records (ID, revision, grower, text) with span evidence; `replace-total`, `add-quantity`, `correction`, `forecast` and `unresolved` operations; blocking questions for any unresolved/conflicting lot, grower, quantity, unit, pack, grade, date or correction target and for unanswered clarifications; clarification answers stored as linked source spans and covered by the review hash; approval bound to the exact review hash; commit rechecks ledger version and snapshot hash; one commit per source revision per lot (primary sources only; citing a source as an answer applies nothing), rejecting duplicates and older revisions; every source ID/revision must name one identical record across primary and answer sources in the proposal and committed history; a correction may target any earlier inventory update on the same lot (the version currently in force for it); the lot is recomputed by replaying its updates in order with each update's newest correction, so later added quantities carry through and a later new total still overrides (the correction is then logged with no inventory effect); review returns the before/after quantity for the coordinator; forecasts recorded in `ledger.forecasts`, outside the allocatable snapshot. The original absolute-total `applyUpdate` API was replaced.

Verified at milestone 1: npm test (17 tests), npm run typecheck, npm run demo (same balances as above). Deliberate breakage of correction replay, in-force targeting, later-total precedence, duplicate, forecast-separation and version checks each failed the suite.

Still open: the ledger is in-memory only, so atomicity is a compare-and-swap contract that a persistent store must enforce; blocked reviews and unanswered questions are not persisted, only committed proposals; forecasts cannot be corrected or retired and lots are not confirmed by updates; fractional quantities, pounds and variable case weights remain unresolved rather than converted; held-out development cases for milestone 1 acceptance have not been independently authored; no model interpretation, UI or Notion/Asana update.

## Milestone 2 — Meta interpretation boundary (October 26, 2026, started)

Official docs checked October 26 (dev.meta.ai): the hackathon names the Meta Model API (Muse Spark series); Chat Completions at `https://api.meta.ai/v1/chat/completions`, bearer `MODEL_API_KEY`, `max_completion_tokens`, `reasoning_effort`, `response_format` json_schema with `strict`, `choices[0].message.content`/`refusal`/`finish_reason`, `usage`. Muse Spark 1.1-1.3 are billed per token; `-contributor` variants license prompts/responses for training and are refused by the adapter until data rights (HTO11) are settled. No model ID is selected by default; callers must pass one.

`src/interpret.ts`: disabled unless `enabled: true`; injected `Transport` seam (`metaTransport` performs HTTP with an explicitly passed key, never read from the environment); request carries the sender's lots (no quantities) and recent updates only, with source text as JSON data outside the system prompt; schema enumerates permitted lot/update IDs; local validation rejects malformed, truncated, refused or filtered output, unknown references and contradictory fields; values lacking a verbatim evidence quote for their field are dropped back to missing; model questions become unanswered clarifications. Output is an unapproved proposal for `reviewUpdate`/`commitUpdate`. Bounds: one call, no retries, call budget charged before the call, timeout <=60 s (default 20 s), <=2000 completion tokens (default 800), request <=32k chars, reasoning effort minimal or low (Muse Spark rejects none with HTTP 400).

Verified: npm test (29 tests, 12 new with injected provider responses), npm run typecheck, npm run demo (unchanged). Deliberately disabling eight safeguards each failed the suite. Not done: no credentials, live or paid calls, model comparison, usage/cost recording beyond the in-memory budget, UI wiring or demo integration.
